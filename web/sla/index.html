SLA court for paid APIs

A buyer paid an x402 API and says the answer was bad. The court rules refund, no refund, or could not decide. Seller in the demo: AgentFeed.

How it works

  1. Plain code first: the validators read the USDC payment from Solana mainnet or Base and check amount, payee, mint and time window. Any failure ends the case there.
  2. The seller's ed25519-signed receipt binds the payment, the resource asked for, the time served and the sha256 of the answer.
  3. Per tool, "delivered" is defined in code: HTTP status, schema, the asset named in the answer, and the age of the data against the SLA.
  4. Only the grey zone (older than promised, younger than the hard limit) goes to five validators with different models, with the live status of the seller as one fact.
  5. The buyer's complaint text is never shown to a model. Answers come from a closed set; unsure means could_not_decide.

1. Pick a case

Each case is a real settled mainnet USDC payment to AgentFeed's treasury. The receipts are signed with a stand-in key and the response bodies are fixtures, because AgentFeed has no signer deployed yet.

2. Judge it on GenLayer studionet
